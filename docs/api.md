# HTTP API

What the schema cannot say. The schema itself is `docs/openapi.json` (generated by `make openapi`), and a running server shows it interactively at `/docs`.

The API is JSON over HTTP, for a single user, without authentication. Todos are kept in memory, so they are gone when the server stops.

## Endpoints

A todo is returned as `{"id": "<uuid>", "title": "...", "done": false, "created_at": "<ISO 8601, UTC>"}`.

| Method | Path | Body | Success | Errors |
| --- | --- | --- | --- | --- |
| POST | `/todos` | `{"title": "..."}` | 201, the new todo (open) | 422 |
| GET | `/todos` | | 200, a list of todos in creation order | 422 |
| GET | `/todos/{todo_id}` | | 200, the todo | 404, 422 |
| PATCH | `/todos/{todo_id}` | `{"title": "...", "done": true}`, each field optional | 200, the updated todo | 404, 422 |
| DELETE | `/todos/{todo_id}` | | 204, empty body | 404, 422 |

`GET /todos` takes an optional query `done=true` (only completed todos) or `done=false` (only open ones). Any other value is a 422. Without it, every todo is returned.

A `todo_id` that is not a UUID is a 422; a well-formed id that no todo has is a 404.

## Title rules

The domain owns these, and every endpoint that takes a title applies them:

- Surrounding whitespace is stripped first, so `"  Buy milk "` is stored as `"Buy milk"`.
- A title that is empty after stripping is refused: `title must not be blank`.
- A title longer than 200 characters after stripping is refused: `title must be at most 200 characters`. Exactly 200 is accepted.

## PATCH rules

- `title` renames the todo. `done: true` completes it, `done: false` reopens it.
- A field sent as `null` counts as not set. A body that sets neither field (`{}`, or only nulls) is a 422.
- The title is applied first. If it is refused, nothing changes, so the `done` flag in the same request is not applied either.
- The id and `created_at` never change.

## Errors

Every error has the same body, with `detail` as its only key and a single sentence as its value:

| Case | Status | `detail` |
| --- | -: | --- |
| Unknown todo | 404 | `todo <id> not found` |
| Refused title | 422 | the rule's message, as above |
| Invalid request (missing field, bad type, bad id, bad filter, empty `PATCH`) | 422 | `<location>: <message>` of the first problem, e.g. `body.title: Field required`, `query.done: ...`, `path.todo_id: ...` |

## Examples

Start the server with `uv run uvicorn app.api.main:app --port 8765`, then:

```bash
curl -s -X POST localhost:8765/todos -H 'content-type: application/json' -d '{"title":"  Buy milk "}'
# {"id":"…","title":"Buy milk","done":false,"created_at":"…"}

curl -s 'localhost:8765/todos?done=false'
# [{"id":"…","title":"Buy milk","done":false,"created_at":"…"}]
```
